# ADR-0001：編輯語義允許模式 A／B，優先 A

- 狀態：已接受（計畫書 v1.1；spec §3「第 0 段選定嚴格模式」之結論：**不採嚴格 A，允許 A/B、優先 A**）
- 日期：2026-10-12
- 需人工確認：否（已確認決策）

## 背景

修改 PDF 既有文字有兩種做法：

- **模式 A（就地改寫）**：在原內容串流中改寫 Tj／TJ 運算元，沿用原字型與座標。排版保真最高，
  但子集字型若缺新字的字形就無法表達。
- **模式 B（移除後重繪）**：移除舊文字的繪製指令，再以可嵌入字型在原位重繪新文字。可處理缺字，
  但字型可能與原文不同，且若只「蓋掉」而未移除，舊文字仍可被擷取（資訊殘留）。

繁中文件普遍使用子集 CID 字型，模式 A 的覆蓋率是 G2 的最大風險。

## 決策

1. 預設走模式 A。
2. 僅當 A 因子集字型缺字無法處理時才走 B，並在 EditPlan 標示模式與原因。
3. 模式 B 必須**證明舊內容已從內容串流移除**（非白底覆蓋），作為 G2 第 5 點驗收條件：
   以擷取工具在儲存後的檔案中找不到舊字串，且舊 Tj／TJ 運算子已不存在。
4. 不採用白底遮蓋、FreeText 註解、只加新文字、整頁點陣化（spec §3 C 類），也不得把這些當作 A／B。
5. 模式 B 必須保留周圍文字與向量內容；PyMuPDF redaction 只能在顯式設定圖片／圖形處理並通過非目標內容檢查後，作為 B 的受限實作（spec §3）。
6. 字型替換（模式 B）須在 EditPlan 的 font_changes 明示，並由人工確認版面變化（spec §1、§8.2）。

## 後果

- P2 先完成模式 A 與證據報告，再做 B 的子集。
- fixture T01、F01（新字在原子集內，模式 A）與 F02（新字不在子集，模式 B）為主要判定樣本；F03（𠮷 無任何已包裝字型）須拒絕。
- 11/10 G2 決策點依 A 的實測覆蓋率決定繼續、收縮支援矩陣或停止。
