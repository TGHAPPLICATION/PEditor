# ADR-0019：PDFium 截斷小數 /Widths 的視覺比對例外（以位置驗證取代像素門檻）

- 狀態：已接受（2026-10-22，工程師於 P2 步驟 5 選定「窄例外＋位置驗證」）
- 日期：2026-10-22
- 決策者：工程師
- 需人工確認：否（已確認）

## 背景

P2 步驟 5 的視覺基準（`reports/P2/visual_baseline.json`）中，T02（ReportLab、Droid Sans Fallback 單位元組 TrueType）
「10 月 31 日」→「11 月 5 日」在 PDFium 的同引擎比對，改動區 +2 pt 外有 305 個像素（0.014%）每通道差 >8/255，
超過 spec §8.2 的 0.01%；同一檔案在 MuPDF 為 0，同檔同寬替換 E04 在兩引擎皆為 0。

查明原因：

- ReportLab 寫入小數字寬（數字 550.7812、空白 261.7188）。PDF 規範的 `/Widths` 為實數；MuPDF 依實數使用。
- **PDFium 將單位元組字型的 `/Widths` 截為整數**（550、261）。以實際 TJ 實驗確認 PDFium 對 TJ 小數位移是精確的，
  差異只來自字寬；以截斷字寬預測 T02 該行原檔在兩引擎的位置差 0.159 pt，實測 0.204 pt（其餘為 MuPDF 回報原點的取整）。
- 模式 A 依規範字寬計算 TJ 補償（ADR-0018 §2）＝ 550.781；PDFium 視新舊字寬差為 550，後續字形因此在 PDFium 移動
  0.781/1000 × 12 pt ＝ **0.0094 pt**（約 0.02 像素），反鋸齒邊緣因而超過像素門檻。實際位置誤差遠小於 §8.2 的 0.5 pt。

新舊字形的「截斷誤差總和」不同時，任何單一補償值都無法讓兩引擎同時不動；這是引擎差異，不是編輯損及鄰區。

## 選項

1. **窄例外＋位置驗證**：只在下列條件全部成立時，PDFium 的改動區外像素門檻改以位置驗證；MuPDF 仍套完整像素門檻。
2. 這類編輯一律拒絕（`UNSUPPORTED_LAYOUT`）：T02 manifest 案例改 reject，支援範圍縮減。
3. 全面改用 1 像素鄰域容許的比對：範圍最大，可能掩蓋真正的鄰區損害。

## 決策

採用選項 1（工程師 2026-10-22 選定）。

### 例外條件（全部成立）

- 模式 A，改動字形所在字型為單位元組字型（非 Type0）。
- 計畫的 `geometry.pdfium_width_residual_pt` 不為 0：
  （新字形截斷字寬總和 − 舊字形截斷字寬總和）−（新字形字寬總和 − 舊字形字寬總和），乘字級／1000 與水平縮放。
  由 worker 在計畫中算出並記錄，測試不得自行放寬。

### 取代的驗證（PDFium）

- 目標之後、同一行的每個字形，PDFium 擷取的原點位移 ≤ |pdfium_width_residual_pt| ＋ 0.01 pt。
- 其他行、其他運算子的字形原點不變（≤ 0.01 pt）。
- 改動區 +2 pt 外的超標像素，只允許出現在目標所在行的垂直範圍內（該行字形外框上下各 2 pt）；行外仍須為 0。

### 不變

- MuPDF 的同引擎比對仍套 spec §8.2 全部門檻；ADR-0015 的 7 份（MuPDF 渲染空白）不在本例外內，
  若同時符合，兩者疊加會使視覺門檻只剩位置驗證，因此這種組合**不適用本例外**，維持 PDFium 像素門檻。
- 目標外框定位 ≤ 0.5 pt（G2-12）、未修改頁像素完全相同（G2-10）不受影響。

## 後果

- `worker/edit.py` 計畫記錄 `pdfium_width_residual_pt`；`tests/integration/test_visual.py` 依此套用例外。
- 報告須逐案列出套用本例外的案例與實測位移。
- 若日後 PDFium 依規範處理小數字寬，本例外自動不再觸發（實測位移為 0 時像素門檻亦會通過）；升級 PDFium 時須重跑基準。
