# ADR-0029：頁面工具（刪除／保留／擷取頁面、合併、插入 PDF）與介面視覺改版

- 狀態：提議（2026-11-13）
- 日期：2026-11-13
- 決策者：工程師
- 需人工確認：**是**（擴大支援範圍：多檔輸入、頁面結構變更；介面改版）

## 背景

工程師 2026-11-13 提供一份 Colab 工具（PyPDF2：刪除頁面、只保留頁面、合併、擷取頁面範圍、插入 PDF、壓縮），
要求加入 PEditor，並以 GUI 設計技能改善介面。工程師的選擇：

- 功能：刪除／保留／擷取頁面、合併多個 PDF、插入 PDF 到指定位置。
- 壓縮：**先不做**（工程師在功能清單勾了壓縮，但壓縮做法選「先不做壓縮」，以後者為準；
  附件的圖片重壓縮會整頁點陣化、文字層消失，與 spec §3 原則衝突）。
- 整合：**獨立「頁面工具」輸出新檔**，不進入編輯的復原與草稿。
- 介面：**整體視覺改版**，先做視覺稿給工程師確認再實作。

## 決策（提議）

1. **不新增相依**：以既有 pikepdf 實作（不加入 PyPDF2）。所有 PDF 只在 worker 子行程開啟（ADR-0004），
   每份輸入都視為不可信，套用 `core/limits.py` 既有上限（檔案大小、頁數、物件走訪）。
2. **一種核心操作**：`compose_pages(sources, plan, destination)`——依「來源檔＋頁碼」清單組成新 PDF。
   四種使用者功能都轉成這個清單：
   - 刪除頁面：目前檔案中「不在範圍內」的頁；
   - 保留／擷取頁面：目前檔案中「在範圍內」的頁，依原順序（擷取＝保留，共用同一畫面，範圍語法 `1-3,5,7-9`）；
   - 合併：多份檔案依使用者排定的順序全部接續；
   - 插入：目前檔案第 1..n 頁＋插入檔全部＋第 n+1..末頁（n＝0 表示最前面）。
3. **輸出**：一律另存新檔，經既有的目的地權杖與原子寫入（ADR-0021）；不覆寫來源檔；成功後詢問是否開啟。
   目前開啟的文件有未另存修改時，先依 ADR-0027 詢問「另存／不儲存／取消」（頁面工具讀的是磁碟上的檔案）。
4. **上限**：輸入檔最多 20 份；輸出總頁數 ≤ `MAX_PAGES`（500）；每份輸入先過既有的開檔檢查（加密、損毀、資源上限即拒絕）。
5. **保留與不保留**（照實告知，不假裝）：保留頁面內容、資源、註解、頁面大小與旋轉；
   **不保留**書籤（大綱）、跨檔的表單欄位（含 AcroForm／XFA 的輸入檔先拒絕，避免欄位名稱衝突）、
   文件層級的標籤結構與 JavaScript。頁面工具結果畫面列出這些限制。
6. **驗證**：寫出後在 worker 重新開啟，比對頁數與每頁內容串流的雜湊等於來源頁，失敗即刪除輸出並回報。
7. **介面視覺改版**：套用 frontend-design 技能的設計原則（配色、字體層次、間距、狀態色）到 Qt：
   - 統一的 QSS 主題（淺色為主；深色依系統設定為選配，另議）；
   - 工具列分組（檔案／編輯／檢視／頁面），圖示使用 Qt 內建標準圖示或自繪 SVG，**不引入有授權義務的圖示包**；
   - 編輯面板、尋找框與新的「頁面工具」對話框共用版面規格；
   - 先交視覺稿（設計稿）給工程師確認，再實作。
8. **不做**：壓縮、頁面旋轉、縮圖拖曳排序、在編輯中直接刪頁（可另案）。

## 後果

- spec §4 支援矩陣新增「頁面工具」一列；§6 新增 P9 段（本 ADR）。
- 新增 worker 子命令 `compose_pages`、核心的頁碼範圍解析、UI「工具 → 頁面工具…」、QSS 主題檔。
- `THREAT_MODEL.md` 新增：多檔輸入、頁面複製的資源放大（同一資源被多頁引用）與輸出大小。
- 驗收：自動測試＋Windows 沙箱實機（新增清單項目）；不影響既有文字編輯的語義與測試。
