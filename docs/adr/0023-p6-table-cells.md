## 背景

spec P6：以文字及線條推估表格／人工確認框；固定框內編輯；複用 P2；同格多行需明確 line layout；移除舊內容但保留邊線。
G6：全部宣告支援 B 案例；邊線幾何／筆畫寬不變、其他格擷取文字及視覺不變；溢出阻擋；無法辨識的格可人工選定但仍需能力判定。
不實作列插刪、合併、跨頁重排，不匯出 Excel。§7：`plan_cell_edit(document_id, cell_id, new_text, expected_revision)`；
§8.2：遮罩不能包含其他儲存格。ADR-0013：B06（合併格）的拒絕延到 P6 由 `plan_cell_edit` 判定。
實測：P2 引擎在給定 manifest 可改動區域時已能改 B01–B05（模式 A／B，另存驗證通過），P6 的重點是表格結構。
B 組的線條有三種畫法：描邊線段（B01、B02、B04、B06）、0.48 pt 細填色矩形（Word：B03、B05）；B06 的合併格是中間直線在該列斷開。

## 決策

### 1. 格線推估與儲存格

- content 解譯器記錄頁面上描邊的直線段（含描邊 `re` 的四邊，線寬依 CTM 換算）與填色的 `re`；曲線、只建路徑（`n`）不記錄。
  每頁上限 20,000 筆（`MAX_RULE_PATHS`），超過即不做表格偵測；合併後水平線數×垂直線數超過 1,000,000
  （`MAX_RULE_PAIRS`，交會判定為平方級）也不偵測。
- 格線：頁面層級（Form 內不算）的水平、垂直線段，以及厚度 ≤2 pt 的填色矩形；換算到頁面空間後，位置差 ≤1 pt 且
  間隙 ≤1 pt 的片段合併成一條線；斜線與較粗的填色（底色）不算。
- 表格：互相交會的水平線與垂直線為一組（至少各 2 條）；線的位置構成網格（單一表格上限 10,000 格）。
  共用邊沒有線的相鄰網格合併；合併後為矩形且四邊都有線者為一格；跨多個網格者為合併格，拒絕 `UNSUPPORTED_LAYOUT`。
- `inspect_page` 新增 `cell_targets`：`cell_id`（revision、頁、表格、列欄、格內緣幾何 hash；spec §7）、列欄與跨度、
  格線中線範圍 `bbox`、扣掉半個線寬的 `inner_bbox`、格內各行（文字、文字目標、外框）與能力判定。
- 格內文字：文字目標外框完整落在格內緣（容許 0.5 pt）者屬於該格，依垂直中心分列、列內依 x 排序；同一列上
  間距大於一個字高的文字分成不同的片段（各自為一「行」）。與格內緣重疊但不在格內者（跨格文字）使該格拒絕。
  格本身只因結構問題拒絕（合併格、跨格文字、空白格）；格內某段文字不支援時只擋它所在的行（第一輪核對 Q3）。
- 障礙線（第一輪核對 Q1、Q2；第二輪核對 R1、R2）：頁面與 Form 內每一個實際畫出的子路徑（描邊或填色、`re` 或任意多邊形、
  含曲線——曲線細分成 16 段折線，第三輪核對 S1：控制點折線不一定碰到曲線）的邊。外框厚度 ≤6 pt 且長度超過
  厚度 3 倍的形狀（填色底線、細框線）整個視為一條線；其餘形狀的水平、垂直邊為障礙線（描邊的線兩端外擴半個線寬，
  涵蓋方形與圓形線帽），斜邊連同線寬另存（斜線表頭等）；只填色的形狀的邊記住所屬形狀，與文字重疊時（粗刪除線、
  底色塊）向量判斷略過，交給墨跡檢查（第三輪核對 S3、S4）。每段都算，不設最短長度（點線）。
  每頁記錄的路徑點數上限 100,000（`MAX_PAINTED_POINTS`，曲線細分後的點也計入），超過即不做表格偵測、人工框選回
  `RESOURCE_LIMIT`，`plan_text_edit` 有給 `editable_region` 時也回 `RESOURCE_LIMIT`（UI 的文字編輯不帶區域，不受影響；
  輪廓文字、地圖等向量很多的頁面較易觸發；第三輪核對 S6）。曲線每條細分成 16 段，頁面有隨機曲線時約 6,000 條
  即觸發（細分前 20,000 條仍可偵測；第四輪核對 T6）。
  格的偵測只用頁面層級的細格線，可改動區域裁切、人工框選檢查、另存前比對用障礙線與斜邊。
- 文字目標本身的能力判定不變（B06 格內文字仍為 support）；但 `plan_text_edit` 改到的文字落在（或跨過）結構上不支援的格
  （合併格、跨格文字）時，沿用該格的拒絕理由，文字層 API 不能繞過格判定（P6 報告 U2，2026-11-04 增補）；
  呼叫端給的 `editable_region` 有垂直障礙線穿過時拒絕（支援的文字都是直立的，新文字只沿基線延伸；第一輪核對 Q4）。

### 2. 一次改一行；空白格不改

- `plan_cell_edit` 多一個 `line_index`（0 起），只改該行；以該行的文字目標組成 span，沿用 P2 `plan_text_edit`
  （模式 A 優先、B 次之、真修改證據）。不自動換行、不重排，新文字超出可改動區域回 `TEXT_OVERFLOW`。
- 可改動區域（也是另存視覺驗證的遮罩）＝格內緣中屬於該行的範圍：與上下行之間取中線（沒有則到格邊），與同一列
  左右的片段之間也取中線；再把範圍裁到不碰任何障礙線（第一輪核對 Q1：外框內含小表格或空白數字格時，
  新文字不能畫進內層格），依線與文字的相對位置（第二輪核對 R3）：
  - 與文字垂直範圍重疊（在文字旁邊）：若也與文字水平範圍重疊，水平線（底線、刪除線）不擋——新文字只沿基線延伸，
    垂直線即穿過文字，該行拒絕 `UNSUPPORTED_LAYOUT`；在文字左右者，裁左右邊界到線為止（扣半個線寬）。
  - 在文字上下者：裁上下邊界。
  文字外框下方 1/4 為底線區，其中的水平線（底線、「姓名：＿＿」的填空線）不擋左右延伸（第三輪核對 S5）。
  裁切後的區域內有斜邊即拒絕 `UNSUPPORTED_LAYOUT`（第二輪核對 R2）。
  接著裁掉註解的範圍（第四輪核對 T1、T2）：頁面上除 Link、Popup 以外的所有註解，不看旗標（Hidden、NoView、Print）
  與圖層（/OC）——MuPDF 不畫的註解，其他閱讀器或列印仍可能畫；註解範圍與文字重疊即拒絕 `UNSUPPORTED_LAYOUT`，
  在文字左右、上下者裁對應的邊界，在斜角方向者取保留面積較大的裁法。
  最後以渲染結果為準再裁一次（墨跡檢查，第三輪核對 S1–S3）：worker 以 MuPDF 150 DPI 渲染目前工作文件的這一頁
  （含 shading、Type3、影像；不套用 /Rotate），扣掉目標文字外框外擴 1 pt 的範圍後，與區域底色（取樣的眾數）
  任一通道相差超過 24 的像素為墨跡（第四輪核對 T1：原為 48，淡灰、淡紅、半透明的線不算）；在文字上方 3/4 的列中
  從文字往左右延伸到第一個有墨跡的欄，再往上下延伸到第一個有墨跡的列。外擴的 1 pt 內，墨跡佔文字列至少一半、
  又延伸到文字列外（上或下）的欄是緊貼文字的直線，也擋（第四輪核對 T3）。渲染範圍最外圈的像素不看：那是邊界
  格線的反鋸齒，邊界已由向量裁過（第四輪核對 T4：文字貼近格線時，原本每一欄都被當成墨跡）。PDF 畫東西的方式無法逐一列舉，墨跡檢查是不依賴畫法的最後一道；向量障礙線仍保留，ADR-0015 的 7 份
  MuPDF 渲染空白檔只靠向量判斷。每次規劃約多 6–90 ms（B01–B05 實測）。不包含同格其他行與其他格。
- 空白格（格內沒有文字）拒絕 `UNSUPPORTED_LAYOUT` 並附說明：spec 範圍是修改既有文字，空格補字等於新增內容。

### 3. 人工選格

- `plan_cell_edit` 可改給 `cell_box`（頁面空間）與 `page_index`；另有唯讀的 `assess_cell_box` 供 UI 框選後顯示判定與行。
- 判定：框內不能有障礙線穿過、不能有斜邊（含 Form 內與任何畫法的線；第一輪核對 Q2、第二輪核對 R1、R2）；不能跨越已偵測的多個格、不能碰到合併格；框內每段文字都要完整在框內且至少一段；
  文字本身要通過 P1 判定；線段過多未做偵測時拒絕 `RESOURCE_LIMIT`。合併格不論偵測或框選一律拒絕。
- 用途是偵測不到的表格（例如只有橫線、沒有框線）。

### 4. 驗證、undo／redo、草稿

- 另存前驗證加一項：有改格的頁面，合併後的格線與障礙線（位置、起訖、線寬，取到 0.01 pt）須與原檔完全相同
  （`rules_changed`）。
- command log 項目 `"op": "cell"`，params 為 `plan_cell_edit` 參數；重播、預覽重新規劃依 op 分派；草稿結構驗證接受 `cell`。

### 5. UI（最小版）

點到已偵測格裡的文字即改為儲存格編輯：側欄顯示「表格第 r 列第 c 欄」，多行格顯示行選擇；不支援的格顯示原因。
工具列「手動選格」：在頁面上拉框，經 `assess_cell_box` 判定後同樣以儲存格編輯。

## 選項（S2 時提出）

- 多行：整格一起改（換行分隔、行數須相同）——一次計畫包含多個 P2 編輯，複雜度高 → 未採用。
- 空白格：允許新增文字 → 未採用（超出 spec「修改既有文字」）。
- 介面：只做 core 與整合測試 → 未採用（之後各段沒有排介面工作）。

## 後果

- 新增 `src/peditor/worker/table.py`、`worker/cell.py`；修改 `worker/content.py`、`worker/analyzer.py`、`worker/edit.py`、
  `worker/export.py`、`worker/server.py`、`core/protocol.py`（`plan_cell_edit`、`assess_cell_box`）、`core/editplan.py`、
  `core/limits.py`、`core/service.py`、`core/drafts.py`、`ui/app.py`、`ui/messages.py`。
- ADR-0013 的 B06 延後項目結束：`tests/integration/test_analyzer.py` 的 `DEFERRED` 移除 B06，改以目標格判定驗證。
  `plan_text_edit` 對 B06 格內文字回 `UNSUPPORTED_LAYOUT`（2026-11-04 增補）；UI 點到格內文字一律走儲存格編輯。
- 任何被四邊線框住的文字（例如 L03 的紅框）也會被視為 1×1 的格，UI 點選後以框內緣作為可改動區域。
- 限制：只認水平、垂直的格線（旋轉表格不偵測）；格線在 Form 內的表格不自動偵測，文字在頁面層級時可用人工選格，
  框選與可改動區域裁切都會檢查 Form 內的線（文字也在 Form 內時，文字本身即不支援）；
  模式 B 改過的那一行再改一次會因同一行混用兩種字型而拒絕（P2 的跨段限制）；
  斜邊（含細分後的曲線）穿過該行的區域即整行拒絕，偏保守（圓角框角落的曲線、斜線表頭的格都不能改）；
  墨跡檢查偏保守：底色塊、比文字長的刪除線會讓新文字不能長過它們（`8e1b844` 時可以）；人工框選的判定（`assess_cell_box`）
  只用向量，墨跡檢查在規劃時才套用（以上 P6 報告 U6 (a)–(c)，工程師 2026-11-04 接受）；
  註解範圍與文字重疊即拒絕（螢光筆、包住整格的方框註解、表單欄位蓋在文字上的格都不能改；P6 報告 U7）；
  與底色相差 ≤24 的極淡線條不算墨跡（第四輪核對 T1，殘餘）；底線區的墨跡與向量都不擋左右延伸，底線區裡的
  小方塊或從下方伸進的短直條可能壓到新文字的下伸部（第四輪核對 T5）；文字本身範圍內的非文字墨跡（例如壓在文字上的 shading 直條）無法和字形區分；
  溢出只檢查基線起訖點（P2），字形墨跡可越過可改動區域邊 ≤2 pt（另存視覺驗證的遮罩外擴 2 pt）。
