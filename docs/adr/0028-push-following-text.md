# ADR-0028：新字較寬時，同一行後面的字往右推（可超過原行尾）

- 狀態：提議（2026-11-12）
- 日期：2026-11-12
- 決策者：工程師
- 需人工確認：**是**（改變 spec §6 P2「替換新字超框一律拒絕」與 ADR-0018 §2、§3）

## 背景

P8 實機回報（2026-11-12）：在 T05 先刪「各」再補回，「各」疊在「單」上。插入錨點已修正（G8-08，ADR-0018 §1），
但查證時發現更廣的問題：依 ADR-0018 §2，改字時目標之後的字形位置不動；新字比原字寬、又沒有空白可填時
（例如「請各單位」→「請各各單位」），新字會疊在後面的字上，而 §3 只檢查新字是否超出可改動區域（預設為選取的那一行外框），
疊字不會被擋下（已知缺陷 F12）。工程師 2026-11-12 選擇「後面的字往後推，可超過原行尾，超過時要能正常顯示」，
並選定「同一行延伸到右邊界」，不做跨行重排。

## 決策（提議）

1. **後面的字跟著移動**：模式 A、B 改字後，**同一個文字顯示運算子**中目標之後的字形，以及同一 BT 內接續在同一行、
   沒有重新定位（中間沒有 `Td`、`TD`、`Tm`、`T*`、`'`、`"`）的後續文字運算子，一起移動「新舊字寬差」。
   新字較寬就往右推；**新字較窄就往左收**，不再留空白（取代 ADR-0018 §2「目標之後的字形位置不得移動」與「新文較短時留白」）。
   以 TJ 位移實作，不改其他運算子的座標。
2. **可延伸範圍（取代未指定可改動區域時的 ADR-0018 §3）**：移動後整行最後一個字形的外框可以超過原本的行尾，
   往右延伸到下列最近者為止：
   - 頁面可見範圍（CropBox）右緣；
   - 同一行高度範圍內、不跟著移動的其他文字、圖片外框；
   - 垂直的表格線或框線（`table.obstacles`）。
   超過就回 `TEXT_OVERFLOW`，訊息說明「會超出頁面或蓋到其他內容」。仍然**不縮字、不換行、不壓字距**。
3. **有指定可改動區域時不變**：儲存格（ADR-0023）、手動選格、盲測案例的 `editable_region` 仍以該框為界，移動後的整行
   （含被推的字）任何一點超出框即 `TEXT_OVERFLOW`。
4. **不做**：跨行或跨段重排、推動下一行、移動其他 BT 的文字、自動換行。
5. 計畫的 `geometry` 增加 `shift_pt`（後續字形移動量）與 `line_end`（移動後行尾），預覽的「修改後」須顯示被推的字。

## 選項（未採用）

- 會疊字就拒絕（改動最小，但工程師要能延伸）。
- 自動換行重排：PDF 沒有段落結構，等於做排版引擎；推到頁尾或下一頁的處理風險高。

## 後果

- 修改 spec §6 P2「替換新字超框一律拒絕」為「超出頁面可見範圍、蓋到其他內容或超出指定的可改動區域一律拒絕，不偷偷縮字」。
- 修改 `worker/edit.py`（模式 A 補償、`_tail_number`、模式 B 的 `split_b`／多段 `tail`）與溢出判定。
- 既有測試預期改變（依本 ADR，不是為了遮掩失敗）：
  `tests/integration/test_edit_text.py::test_following_glyphs_unmoved`（G2-19）改為「後續字形移動量＝字寬差」、
  `::test_overflow_rejected`（G2-06）改用會超出頁面或撞到其他內容的案例；新增「較寬時推字不疊字」「較窄時往左收」
  「推到 CropBox 右緣、撞到表格線、撞到同一行其他文字時拒絕」「指定可改動區域時仍以框為界」等測試。
- 支援矩陣（`test_release_matrix.py`）與 fixture 回歸需全部重跑；結果寫入 P8 報告或下一段報告。
- 已知缺陷 F12 移除；實機驗收清單新增推字案例。
