# ADR-0033：「文字擷取」與「頁面管理」改名

- 狀態：已接受（2026-11-24，工程師要求）
- 日期：2026-11-24
- 決策者：工程師

## 背景

同仁有時需要複製 PDF 上的文字。工程師要求：選單「工具 → 頁面工具」改名「頁面管理」；工具列的「頁面工具」按鈕改名並移到「另存新檔」右方；
其右新增「文字擷取」：輸入頁碼，把這些頁的文字合併到可選取的介面，並提供複製。工程師選擇：預設目前頁、每頁加「第 N 頁」標題、
擷取目前畫面（含未另存的修改）、另提供搜尋與另存 .txt。

## 決策

1. **改名與位置**：動作、選單、對話框標題「頁面工具」→「頁面管理」（功能不變，ADR-0029）。工具列第一組為「開啟｜另存新檔｜頁面管理｜文字擷取」，
   取消原本靠右的位置。
2. **worker 操作 `extract_text`（只讀）**：參數 `page_index`；回傳 `{"text", "limited"}`。取目前工作文件（含已套用、未另存的修改）該頁文字，
   依內容串流順序（`get_text("text")`；`sort=True` 會在每行間插空行，不用），去除行尾空白。內容超過處理上限的頁不交給 MuPDF（`limited=true`，同 render_page）；
   單頁超過 1,000,000 字即 `RESOURCE_LIMIT`。不做 OCR：掃描圖片頁回傳空字串。
3. **對話框**（`ui/text_extract.py`）：頁碼欄（預設目前頁，語法同頁面管理 `1-3,5`；欄位下方說明「可自行輸入頁碼…整份請輸入 1-N」）、「擷取」、搜尋欄與「找下一個」（到底從頭找）、唯讀可選取的文字區、
   「移除頁碼」（切換；拿掉「第 N 頁」標題與無文字頁的說明，再按「加回頁碼」，重新擷取時維持）「複製全部」「另存文字檔…」「關閉」。每頁前加「—— 第 N 頁 ——」；沒有文字的頁顯示「（此頁沒有可擷取的文字，可能是掃描圖片）」。
   逐頁同步向 worker 取（對話框開啟時沒有其他工作；每頁各自逾時）。
4. **另存 .txt**：UTF-8 含 BOM（舊版記事本、Excel 可正確辨識中文）、換行依作業系統；副檔名不是 .txt 即補上（不可能覆寫 PDF）；
   在主行程寫入（純文字，不解析 PDF）：先寫暫存檔再換上，失敗不留半個檔；補上 .txt 後的檔名已存在時不覆寫（沒經過對話框的覆寫確認）；
   訊息只顯示檔名，失敗訊息不含路徑。
5. **全部介面不超出螢幕**（2026-11-24 實機回報：高 DPI 時對話框下方按鈕超出畫面、文字被遮住）：`ui/screen.py`。主視窗與所有對話框的預設大小
   不超過螢幕扣除工作列的可用範圍；第一次顯示時整個框移回範圍內（主視窗之後的還原不再移動）；只縮可捲動的內容，按鈕維持建議尺寸。
6. 擷取失敗或頁碼錯誤時清空舊結果；一次擷取合計超過 20,000,000 字即停止並提示縮小範圍。頁碼參數拒絕 bool（`_check_index`，所有以頁碼為參數的操作）。

## 後果

- 文件文字會進入剪貼簿或使用者選的 .txt：屬使用者明確操作；不寫入日誌（THREAT_MODEL T17）。
- 很多頁時擷取期間畫面暫停回應（同步）；頁數上限 500。
- 文字順序依 PDF 內容串流，多欄或表格排版的順序可能與視覺不同。
- 測試：`tests/integration/test_extract_text.py`、`tests/gui/test_text_extract.py`、`tests/gui/test_theme.py::test_toolbar_groups_and_primary`、`tests/gui/test_screen_fit.py`。
- 多螢幕：預設大小以建立時的螢幕（通常是主螢幕）計算，顯示時再依實際所在螢幕移回；最小尺寸大於可用範圍時仍可能超出（目前各介面最小尺寸都小於 1093×574）。
