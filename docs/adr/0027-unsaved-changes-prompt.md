# ADR-0027：關閉或開啟另一份文件前，提醒尚未另存的修改

- 狀態：已接受（2026-11-11，工程師確認「照這個設計做」）
- 日期：2026-11-11
- 決策者：工程師
- 需人工確認：否（已確認）；ADR-0020 §5 的草稿語義不變

## 背景

P8 實機驗收（S13）發現：依 ADR-0020 §5，按視窗 ✕ 正常關閉時 `close_document` 會刪除復原草稿；
開啟另一份檔案（`open_path`）也一樣。因此「改了沒另存就關閉或換檔」時，修改直接消失，**沒有任何提醒**
（已知缺陷 F11，P8 報告 U5）。復原草稿只在當機或強制結束後留下。工程師 2026-11-11 決定要加提醒。

## 選項

1. **關閉或換檔前詢問「另存／不儲存／取消」**：沿用一般桌面程式的做法；草稿語義不變（選「不儲存」仍刪草稿）。
2. 正常關閉也保留草稿、下次啟動再詢問：要改 ADR-0020 §5 與 P4 U11 既有測試的預期；含新文字的草稿會留在磁碟更久（THREAT_MODEL T13）。
3. 維持現狀，只列已知缺陷。

## 決策

採用選項 1：

- **有未另存修改的判定**：UI 記錄開檔與每次另存成功時的 `revision`；目前 `revision` 不同即視為有修改。
  套用、復原、重做都會改變 `revision`，所以「改了再全部復原」也會詢問（保守，不另外比對內容）。
- **詢問時機**：關閉主視窗（✕、選單）、開啟另一份檔案。沒有開啟文件、或沒有未另存修改時不詢問。
  啟動時的復原草稿流程（沒有開啟中的文件）不受影響。
- **對話框**：「這份文件有尚未另存的修改，要先另存嗎？」，按鈕「另存…」「不儲存」「取消」（Esc＝取消）；不顯示檔名或路徑。
  - 另存…：開啟既有的另存對話框並另存；另存成功才繼續關閉或換檔；使用者取消另存對話框或另存失敗，則停在原文件。
  - 不儲存：照現行流程（`close_document`，草稿刪除）。
  - 取消：什麼都不做，停在原文件。
- 進行中的工作（套用、另存）時關閉：照 ADR-0021 §2 的關閉流程處理，**不詢問**（P4 U11 關閉中不再跳出其他對話框）；
  這種情況下仍可能遺失修改，列已知缺陷。
- 復原草稿後的文件視為有未另存的修改。

## 後果

- 已知缺陷 F11 改為只剩「工作進行中關閉不詢問」。
- 新增 GUI 測試（test ID 記入 `docs/traceability.md`）：有修改時關閉／換檔會詢問；取消不關閉；不儲存則關閉且草稿刪除；
  另存成功後關閉；另存取消或失敗不關閉；沒有修改、或另存後不詢問。
- 實機驗收清單新增一項（關閉前提醒），並以新安裝包重測 S06、S13、S14。
- 不改 ADR-0020 §5、P4 U11 既有測試預期（「正常關閉刪除草稿」仍成立，只是先詢問）。
